## Description
Adds a comments section to the site's 404 page so a lost visitor can report a broken link right where they got lost. Reuses the step-06 runtime as-is — the new work is build-time only: one deliberate fixed thread identity for the 404 page and a render path that survives the 404 page's minimal frame (which has no `afterBody` slot).

## High-Level

### Intended outcome
- The 404 page carries the comments section, mounted by the step-06 runtime with no new runtime code paths.
- One deliberate fixed thread: `id: "404"` → `url = https://taras.life/comments/404`. One known thread, created only when the first comment lands; never auto-created per-URL.
- Every missing URL serves the same static `404.html` (`not_found_handling: "404-page"` in `wrangler.jsonc`), so identity is fixed regardless of which URL the visitor actually hit — the thread never needs to know the broken URL unless the visitor writes it in the comment.
- remark42 is unexcluded for the `404` page type in `quartz.config.yaml`, and the section renders inside the 404 body.

### Local invariants
- Fixed identity is frozen like any D4 identity: changing `id` or the derived `url` orphans the thread — a deliberate migration event, same discipline as `THREAD_BASE_URL`.
- The 404 identity is code-owned, not content-owned: the 404 page is generated with no authored frontmatter, so the fixed `id` + `page_title` are hardcoded in the render path, validated with the same `checkThreadId` format rules, and are structurally unique (single call site — no scan participation needed).
- The fixed identity must never be re-derived from `window.location` — that is the per-URL thread explosion this step exists to avoid.
- Placement is build-time work: the section sits inside the 404 body (after the home link), not in the outer frame.
- Zero runtime changes by default. If the step-06 runtime turns out to carry a content-page assumption that breaks the 404 mount, that is a step-06 deviation to record — not a silent patch.
- The 404 section shares the content pages' markup contract: same `section.remark42-comments` wrapper, `script#remark42-config`, `div#remark42`, no eager embed tag (post-step-06). Step 08 styles both uniformly via the shared class.

### Should NOT be done in this step
- No per-URL threads from arbitrary missing URLs — the fixed `id` is the whole point.
- No counters, last-comments, redirects, analytics — D6 scope frozen.
- No runtime changes unless a step-06 deviation forces one (recorded, not silent).
- No styling beyond the existing minimal rule (step 08 owns visual polish).
- No markup-contract changes for content pages — the 05 contract is untouched; the 404 identity is a deliberate, recorded exception.

## Discussion & Reflections

   - (a) Edit `quartz/components/pages/404.tsx` to render the comments section inside its `<article>`; source the markup from the plugin rather than duplicating it — the package already exposes a `./components` export (D1), so a shared renderable (parameterised by `id`/`page_title`) can serve both the afterBody component and the 404 body. One vendored edit, no markup duplication.
   - (b) Switch the 404's frame to one that renders `afterBody` and remove the exclude only — no vendored body edit, but drags sidebars/header chrome onto the 404 page and couples the 404's whole look to a frame choice.
   - (c) Generic "slot into any page body" machinery — new unproven machinery for one page.
