## Description
Added the comments section to the site's 404 page so a lost visitor can report a broken link right where they got lost. Because every missing URL serves the same static `404.html` (`not_found_handling: "404-page"`), the thread is one deliberate fixed thread: `id: "404"` → `https://taras.life/comments/404` — the visitor names the broken link in the comment itself.

## What was implemented

- **Fixed code-owned identity.** `id: "404"` injected into the virtual 404 page's *generated* frontmatter in `quartz/plugins/pageTypes/404.ts` (one vendored edit, single call site — no scan participation, structurally unique). The generated title was set to "Report a broken link", which also becomes the thread's `page_title` in Remark42 admin. Identity frozen like any D4 identity: changing it orphans the thread.
- **Render path is config-driven, not plugin-parametrized.** `byPageType["404"]` in `quartz.config.yaml` sets `template: default` (the minimal frame renders no `afterBody`), un-excludes remark42, and excludes `@quartz-community/content-meta` (the reading-time line rendered under the 404 title). The Remark42 component then treats the 404 like any commentable page via its normal frontmatter path.
- **Intro copy in the 404 body** (`quartz/components/pages/404.tsx`, vendored edit): standing sentence asking the visitor to leave the broken link in a comment. It cannot live inside `#remark42` — the loader wipes all non-iframe children of the container on init.
- **Zero runtime changes.** The step-06 runtime ships site-wide in `404.html` regardless of frame (component scripts are collected globally, not per-frame) and mounts on the initial-load `nav` event exactly as on content pages.
- Live-verified on the deployed Worker: widget mounts behind the viewport gate, single shared thread across every bogus URL, never re-derived from `window.location`.

## Deviations caught during the step
1. Render path flipped from the locked option 1(a) (vendored `404.tsx` + shared parametrized plugin renderer + `.d.ts` emit) to the config-driven shape above — no plugin changes at all, which mooted the D1-typing discussion entirely.
2. `<h2>Comments</h2>` heading stays on the 404 section (component untouched); the report affordance is carried by the body intro copy instead of a custom heading.
3. Config-loader nuance: `byPageType.*.exclude` entries must match the **full scoped npm source name** (`@quartz-community/content-meta`) — `extractPluginName` only basenames local paths. Bare names silently no-op.
4. Early attempts with a broken exclude list (`- ` bare item) and/or missing `template:` produced misleading "didn't work" results before the correct config landed.
