## Description
%%What this step is about%%
Removes Quartz scaffolding machinery: the 4 CLI template yamls and the entire `create` CLI path ([C13] lean: full removal — repo is the site, not a distribution). **Scope expanded mid-step (user decision):** all remaining git/upstream CLI machinery dies too — `upgrade`/`update`, `sync`, `restore` commands with their handlers, orphaned helpers and constants — leaving the CLI with `build` (+ `plugin *`, `tui`). Tier-3 items (deprecated plugin aliases, external plugin-install subsystem) were considered and **explicitly dropped by the user — do not resurrect, do not park**.

## Files affected (final state)
- `quartz/cli/templates/` — deleted entirely (`git rm -r`, confirmed absent on disk).
- `quartz/cli/handlers.js` — lost `handleCreate`/`handleUpgrade`/`handleSync`/`handleRestore`, `resolveContentPath()`, and all create/git-only imports (`intro`/`select`/`text`/`outro`, `rm`, `CreateArgv`, `escapePath`, async `symlinkOrCopy`, `exitIfCancel`, `handlePluginResolve`, `gitPull`/`stashContentFolder`/`popContentFolder`, git constants, `LOCKFILE_PATH`, `execSync`/`spawnSync`).

- `quartz/cli/args.js` — `CreateArgv` and `SyncArgv` deleted; `CommonArgv`/`BuildArgv` intact.
- `quartz/cli/plugin-data.js` — create-flow exports removed; lockfile/source/manifest family stays load-bearing for `plugin-git-handlers.js` (Tier-3 drop does not touch it).
- `quartz/cli/helpers.js` — reduced to `symlinkOrCopySync` alone (+ Windows-fallback doc); it is load-bearing for local plugin linking in `plugin-git-handlers.js`.
- `quartz/cli/constants.js` — reduced to `version`, `fp`, `cacheFile` (build-consumed); lost `UPSTREAM_NAME`, `QUARTZ_SOURCE_REPO`, `QUARTZ_SOURCE_BRANCH`, `ORIGIN_NAME`, `contentCacheFolder`, `cacheDir`, `cwd`, and the `path` import.
